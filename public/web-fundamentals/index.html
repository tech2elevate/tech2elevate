index.html: the browser reads top to bottom

<!DOCTYPE html>
<html>
  <head>
    <title>Tech Shop</title>
    <link rel="stylesheet" href="styles.css" />
  </head>
  <body>
    <div id="product-list" class="product-grid"></div>

    <h2 class="section-title">Your Cart</h2>
    <p id="empty-cart-message">Your cart is empty.</p>
    <div id="cart-items" class="cart-items"></div>
    <div id="cart-total"></div>

    <script src="script.js"></script>
  </body>
</html>

Why it is ordered this way

<link>Goes in <head> so styles load before anything appears.
<script>Goes just before </body>. The browser reads top to bottom, so every element already exists when JavaScript looks for it.
empty ids#product-list and #cart-items start empty. They are placeholders JavaScript fills in later.
⚠ order bugIf <script> runs in <head>, getElementById("cart-items") returns null because the cart list has not been read yet.

  Part 1 · The DOM
  
The DOM is the page as a family tree

  
The browser turns your HTML into a tree of objects called the Document Object Model. JavaScript starts at document and works its way down to find any element.

  

   

   

    
Every element object has properties you can read and change

     

      
.textContentThe plain text inside

      
.innerHTMLThe HTML inside, as a string

      
.classNameThe class attribute, as text

      
.classList.add()Add one class without removing others

      
.dataset.idReads the data-id attribute

      
.style.displayShow ("block") or hide ("none")

      
.appendChild()Add a child element inside this one

      
.addEventListener()React when something happens to it

Before JavaScript can change something, it has to find it. Each method asks the document a different kind of question.

querySelector


document.querySelector("p");          // tag

  Part 5 · Functions
  
Functions are reusable recipes

  
A function is a named set of steps. You define it once, then call it whenever you need it. Hover each part:

  

   

    
function addToCart(productId) {
  const product = products.find(...);
  ...
}

addToCart("game"); // call it

    
Hover a colored part of the function ↑

    
Arrow functions: the short form


// These two do the same thing:
function (p) { return p.id === productId; }
(p) => p.id === productId

     
You see arrow functions inside forEach, find, and addEventListener. They're small functions handed to another function.

   

   

    
The 5 functions of the shopping cart

    

     
createProductHTML(product)
Takes one product object and returns its card HTML as a string. · Week 4

     
displayProducts()
Loops through products and puts a card on the page for each one. · Week 4

     
addToCart(productId)
Finds the product. If it's already in the cart, adds 1 to its quantity; if not, pushes a new item. · Weeks 5–6

     
updateCart()
Clears the cart list, then redraws every item, the Remove buttons, and the total. · Weeks 6–7

     
removeFromCart(productId)
Finds the item's index, then subtracts 1 from its quantity or splices it out. · Week 7

    

   

  

 







 

  Part 5 · Functions
  
Who calls whom?

  
The functions call each other in a chain. Press a trigger to watch the chain run.

  

   
displayProducts()→products.forEach()→createElement("div")→createProductHTML(product)→appendChild(card)→addEventListener("click")

   
listener runs→button.dataset.id→addToCart(id)→products.find()→cart.find()→push() or quantity++→updateCart()

   
listener runs→removeFromCart(item.id)→cart.findIndex()→quantity-- or splice()→updateCart()

   
innerHTML = ""→let total = 0→cart.forEach()→price * quantity→createElement("div")→Remove button + listener→appendChild()→total.toFixed(2)

  

  
Key rule
Every time the cart array changes, call updateCart() so the page matches the data. The data is the source of truth; the page is a picture of it.

  Part 5 · Listen
  
Event listeners make the page respond

  
An event is something that happens: a click, the mouse moving over an element, or a key press. A listener is the function that runs when its event happens.

  
button.addEventListener("click", () => {
  addToCart(button.dataset.id);
});

  

   
1. WHO
The element to watch, found with querySelectorAll

   
2. WHAT
The event name: "click", "mouseover", "keydown"

   
3. THEN
The function to run. It waits and does not run until the event happens.

  Part 6 · Debugging
  
Common bugs and how to fix them

  
Open DevTools (right-click → Inspect → Console) and add console.log(something) to see what's really in a variable.

  

   
"Cannot read properties of null"
The id in getElementById doesn't match the HTML, or it includes a #.
✔ Copy the exact id from index.html

   
No products appear
displayProducts is defined but never called.
✔ Add displayProducts();

   
Cart data changes, page doesn't
The cart array was updated but the page was never redrawn.
✔ Call updateCart() after every change

   
Items appear twice
updateCart adds rows without clearing the old ones.
✔ Start with innerHTML = ""

   
Add button does nothing
Listeners were attached before the cards were created, or the class name has a typo.
✔ Attach after displayProducts()

   
find returns undefined
dataset.id is always a string. "1" === 1 is false.
✔ Use string ids, like id: "1"

   
Price shows 59.980000001
Computers can't store some decimals exactly.
✔ Display with .toFixed(2)

   
Remove button does nothing
No listener was attached when the button was created.
✔ Add addEventListener inside updateCart
